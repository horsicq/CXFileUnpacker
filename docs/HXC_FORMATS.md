# HxC disk image formats

The [HxC input format list](https://hxc2001.com/docs/gotek-floppy-emulator-hxc-firmware/pages/emulation-from-images.html) was audited on 2026-10-03 against HxCFloppyEmulator commit `3c9ab41127991797f0a9563f529f602fdb177e36`. The audit maps all 210 table rows: 50 firmware entries, 91 software modules and 69 XML presets. Existing readers cover many aliases. This update adds 23 container/track readers, one explicit raw-layout reader with 102 named profiles, and one XML descriptor reader. Format IDs previously assigned by xxfclib retain their values.

| New reader | Extraction representation |
| --- | --- |
| `amiga_ext_adf`, `amiga_old_ext_adf` | Extended ADF descriptors and stored sector/MFM tracks. |
| `atari_dim` | Full DIM sector image; sparse used-sector DIM retains its original payload and reports that logical reconstruction is unavailable. |
| `atari_stt`, `atari_stw` | Indexed STT/STW track components. |
| `discferret_dfi` | DiscFerret DFER/DFE2 flux captures. |
| `hxc_afi` | CRC-validated AFI records; supported zlib blocks decoded, reserved packers preserved as opaque components. |
| `hxc_qd` | QD descriptors and bounded track data. |
| `hxc_stream` | Pauline CHKH packets, CRC32 validation, exact LZ4 decoding and pulse framing. |
| `svd` | Author's 1.2/1.5/2.0 Semi-Virtual Diskette framing; stored blocks retained, WD tracks additionally unrotated. |
| `sdu` | SAB Diskette Utility header and sector payload. |
| `fei` | Side-major LSB-first MFM tracks; automatic recognition requires valid IBM address CRCs and consistent boundary geometry. |
| `oric_dsk` | Oric ORICDISK sectors or MFM_DISK track data. |
| `ensoniq_gkh` | Tagged GKH disk geometry and sectors. |
| `ensoniq_ede` | Native EDE/EDA/EDS/EDT/EDV bitmap reconstruction, including mixed Mirage/DPX sectors. Computer-format flag 1 has unresolved geometry and is rejected. |
| `samcoupe_sad` | Aley's SAD header and sectors. |
| `apple_nib` | 6656-byte Apple II nibble tracks with verified DOS3.3 address/data checksums. |
| `ti99_pc99` | PC99 FM/MFM token tracks with sector framing and stored/controller-generated CRC validation. |
| `emax_disk`, `emulatorii_eii` | Stored sample and bank blocks. Missing OS data is reported as an incomplete disk dependency; no replacement OS is synthesized. |
| `casio_fzf` | Explicit Casio full/bank dumps, including validated multi-bank metadata and canonical metadata-free one-bank dumps; bank, voice and PCM components. Split continuations and unknown layouts are rejected. |
| `vtr_disk` | VTrucco indexed track-sector blocks. |
| `speccydos_sdd` | SpeccyDOS TRKY2 side-sequential sectors. |

These are original MIT implementations based on public format facts. Encoded track and flux extraction preserves the stored representation; it does not promise filesystem recovery or full emulation of protected disks. Existing A2R support also accepts A2R3 SLVD captures and multi-track captures exceeding 1 MiB within its bounded input limit. Thomson FD now has an explicit `thomson_fd_hxc` reader for the HxC 80-cylinder, one-head 320 KiB interpretation; the existing 40-cylinder, two-head interpretation remains available as `thomson_fd`.

## Explicit raw geometry

Headerless images cannot identify their geometry through file size or extension alone. List the profiles and choose one:

```text
xfu --raw-profiles
xfu l disk.img --reader hxc-raw:DOS_DD_720KB --advanced
xfu x disk.img --reader hxc-raw:ENSONIQ_EDM -orecovered
xfu x bank.fzf --reader casio_fzf -orecovered
xfu x samples.eii --reader emulatorii_eii -orecovered
```

The raw reader requires the profile's exact source length. It exports both the complete original image and logical cylinder/head/sector data, honoring mixed sector sizes, side ordering and declared source offsets. Unformatted tracks contain no invented sectors. Profile tracks outside the source extent use declared fill and are identified as generated bytes in `Comment` metadata. Source bytes take priority over boot-sector templates; unused source padding remains in the original image.

The public API in `xx_hxc_raw_floppy.h` provides profile enumeration and lookup, `create_profile`, a deep-copying `create_layout` for caller-declared extents, and `create_layout_xml` to apply a supplied XML descriptor to an explicitly supplied raw device. Layouts may use source runs, inline data and fill runs. Source offsets are relative to the reader's base address. Generic/variable geometries require an explicit caller layout rather than an inferred machine identity.

## XML descriptors

`hxc_xml_disk_layout` reads the HxC `disk_layout` schema, including default geometry, per-track overrides, empty tracks, per-sector sizes/IDs/offsets, fill values and inline hexadecimal `sector_data`. It exports the original descriptor plus an initialized logical sector image. It retains timing, encoding, CRC/weak-bit declarations in the original XML; it does not turn them into magnetic track data. XML input by itself contains no external raw-image bytes, so the output metadata identifies descriptor initialization. No descriptor path, DTD or external entity is opened. To map an external raw image, the caller explicitly supplies its device to `create_layout_xml`.

The published FLEX 40-cylinder descriptor appends cylinder 40. As HxC does, the reader omits that bounded trailer from the declared disk geometry; it preserves the full XML and reports the omitted declaration in metadata. Hard bounds, malformed structure, duplicate tracks/sector IDs, invalid hex and arithmetic overflow remain errors.

AMIGA_FS, FAT12FLOPPY and SNES_SMC are host-input/image-generator operations, and BMP_IMAGE/BMP_DISK_IMAGE are exporters/generators. They introduce no additional input disk container. Their role and every page alias are recorded in the [coverage matrix](HXC_COVERAGE.md) and the machine-readable `tests/hxc_page_coverage.json`.

Verification includes independent structured-format byte fixtures, exact raw/XML extraction comparisons, a real Casio factory FZF control, all 102 compiled profiles, all primary XML presets, malformed inputs, checksum failures, resource limits, cancellation, short reads, ownership and nonzero base/cursor checks.
